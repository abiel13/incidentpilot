# IncidentPilot POC limitations

- **Simulated environment:** source data and effects are seeded in SQLite. Production use needs authenticated, read-only telemetry adapters with tenant isolation and retention controls.
- **Single process:** FastAPI background tasks, rate limits, and resume locks are in-process; the SQLite compare-and-set prevents duplicate review claims for the shared database, but distributed workers, queueing, leasing, and operational recovery need a production job system.
- **Simulated action boundary:** actions write only to the demo configuration table. A production remediation connector needs least-privilege credentials, independent policy checks, audit retention, rollback/compensation design, and approval identity.
- **Access:** production mode uses one shared HTTP Basic account, per-process rate limits, request limits, and same-origin checks. It has no individual reviewer identity or role-based authorization. Share credentials separately and rotate them after the demo; production needs SSO and proper audit controls.
- **Model quality:** Gemini diagnoses and confidence are model-generated, not independently verified or calibrated. Evidence IDs are checked for existence, not semantic support. Prompt injection and hallucinations remain possible; the human reviewer must inspect the evidence. The OpenAI-compatible mode has not been live-verified here.
- **Memory:** verified lessons are matched by incident category and capped to a few recent records. Production needs ownership, provenance review, quality scoring, deletion policy, and retrieval controls.
- **SQLite:** application data and LangGraph checkpoints share a single SQLite file. A deployment would require durable storage and one process. Local restart was tested; hosted persistence has not been verified. A larger deployment needs managed storage, backup/restore testing, and migration controls.
- **Streaming:** the UI replays persisted events over SSE; this POC has no distributed event broker or multi-tenant authorization boundary.
- **Branching:** the selected state snapshot seeds a new investigation with a fresh thread ID. It does not mutate or resume the source thread and is intentionally shown as a new branch.
- **Custom reports:** new incident descriptions are preserved as user-reported evidence. The generic simulator does not fabricate service logs, metrics, or change records for them.
- **Verification:** only approved simulated configuration values are compared. Traffic, job, and service recovery are not measured; an incident without an actionable simulated change ends inconclusive.
- **Data sent to Google:** Gemini receives incident context, simulated evidence and findings, and matching stored lessons. Review the provider's data and billing terms before using real incident data.
